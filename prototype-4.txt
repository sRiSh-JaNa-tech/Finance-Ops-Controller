1. EXECUTIVE SUMMARY & MOTIVATION
----------------------------------------------------------------------------------------
Prototype 3 operated as a "pseudo-agent": it pre-executed deterministic financial rules, 
injected the entire rule evaluation into a massive single-shot prompt, and asked Gemini to 
output structured classification JSON. The resulting "tool logs" (e.g., inspect_entity_graph)
were hallucinated text rather than real function executions. Furthermore, the benchmark 
conflated matching with exception triage into a single inflated F1 score and used an 
arbitrary 0.80 confidence threshold.

Prototype 4 refactors the system into a mathematically grounded, genuine ReAct agent 
with native tool calling, asymmetric decision theory, and multi-axis evaluation.

2. MATHEMATICAL FOUNDATION: PROBABILISTIC RECORD LINKAGE & DECISION THEORY
----------------------------------------------------------------------------------------
[Reference: Fellegi & Sunter, 1969 - "A Theory for Record Linkage", JASA]
[Reference: Angelopoulos & Bates, 2021 - "Conformalized Abstention Policies (CAP)"]

A. The Three-Way Decision Space
   Fellegi-Sunter proves that linkage over comparison vectors γ ∈ Γ must be framed as:
     - Action A1 (Positive Link):  Mapped to DecisionLabel.MATCHED
     - Action A2 (Possible Link):  Mapped to DecisionLabel.UNCERTAIN (Human Review Queue)
     - Action A3 (Non-Link):       Mapped to DecisionLabel.EXCEPTION (Triage / Anomaly)

B. Asymmetric Cost-Weighted Decision Boundaries
   In financial ledger reconciliation, errors carry asymmetric operational penalties:
     - B    = $25   (Benefit of a correct automated ledger match)
     - c_FP = $500  (Cost of a false match: ledger corruption / audit violation)
     - c_FN = $50   (Cost of a missed real match)
     - c_U  = $10   (Cost of manual accountant review)
     - c_E  = $50   (Cost of an unexplained exception)

   The optimal upper threshold for full automation (τ_auto) is derived as:
     τ_auto = 1 - (c_U / c_FP) = 1 - (10 / 500) = 0.980 (98.0%)

   Decision Policy:
     - If P(Match | Evidence) >= τ_dynamic  ==> MATCHED (Automated Ledger Reconciliation)
     - If P(Match | Evidence) < τ_exception ==> EXCEPTION (Automated Dispute/Fault Filing)
     - Otherwise                            ==> UNCERTAIN (Escalated to Human Accountant)

C. Context-Adaptive Dynamic Risk Boundaries (CAP)
   Static thresholds fail because different matching patterns carry disparate intrinsic risks.
   We scale the baseline dynamically based on semantic provenance (ReasonCode):
     τ_dynamic = max(τ_auto, Baseline_instance)
       * EXACT_IDENTIFIER_MATCH (UTR / Invoice Ref match) : Baseline = 0.900
       * FEE_ADJUSTED_MATCH / SPLIT_PAYMENT_MATCH         : Baseline = 0.950
       * FUZZY_ENTITY_MATCH (High semantic risk)          : Baseline = 0.990

3. ARCHITECTURE: GENUINE NATIVE FUNCTION CALLING & ReAct LOOP
----------------------------------------------------------------------------------------
[Reference: Berkeley Function Calling Leaderboard (BFCL)]
[Reference: Yao et al., 2023 - "ReAct: Synergizing Reasoning and Acting in Language Models"]

A. Elimination of Single-Shot Hallucinations
   - Replace the static monolithic prompt with the official Gemini `tools` parameter 
     declaring JSON schemas for all InvestigationToolbox methods:
       1. test_reconciliation_hypothesis(hypothesis_type, record_ids, expected_delta_paise)
       2. run_financial_rules(source_txn_ids, target_txn_ids, rule_category)
       3. get_related_events(txn_id, event_types)
       4. inspect_entity_graph(merchant_id, transaction_id)
       5. retrieve_candidates(query_id, amount_tolerance_pct, date_window_days)
       6. search_source_history(search_term, lookback_days)

B. Multi-Turn Autonomous ReAct Loop
   1. OBSERVE: Agent receives the source transaction and candidate cluster.
   2. REASON: Agent generates an internal chain-of-thought hypothesis.
   3. ACT: Agent returns a native `functionCall` to the Python runtime.
   4. EXECUTE: Python invokes the local deterministic engine and returns `functionResponse`.
   5. CONVERGE: Loop repeats up to 5 steps until the agent outputs final audited JSON.

C. Diagnostic Fault Tolerance & Honest Accounting
   - If the Gemini API times out or throws an error, the system does not crash or silently 
     mask it as a success. It logs an explicit `gemini-error-fallback` record.
   - AI network latency is separated from rate-limiting pacing sleeps (`time.sleep(4)`).

4. CANDIDATE SELECTION OVER PAIRWISE MATCHING
----------------------------------------------------------------------------------------
[Reference: Fu et al., 2025 - "BoostER: In-context Clustering-based Entity Resolution"]

Pairwise matching (`target = candidates[0]`) blinds the agent to multi-candidate realities 
such as Split Payments (where candidates A + B together balance Source).
- MultiPassBlockingEngine indexes and retrieves top-K candidate clusters.
- The entire candidate cluster is passed into the agent's context in one prompt.
- The agent solves an N-to-M subset selection problem rather than binary 1-to-1 comparison.

5. BENCHMARK RIGOR & MULTI-AXIS EVALUATION
----------------------------------------------------------------------------------------
[Reference: Chang et al., 2024 - "A Survey on Evaluation of Large Language Model Agents"]
[Reference: CostBench - "Evaluating LLM Agent Utility Under Cost Constraints"]

A. Separation of Match Quality vs. Triage Quality
   F1 score is separated into distinct operational metrics:
     - Match F1: Precision and Recall specifically for positive reconciliations (MATCHED).
     - Triage F1: Precision and Recall specifically for exception detection (EXCEPTION).
     - Cause-Diagnosis Accuracy: Exact multiclass reason code diagnosis against ground truth.

B. Real-Time Console Streaming
   Benchmark outputs live case-by-case progress with latency, tool count, and engine type:
     `Case 002/100 [S02_FEE_ADJUSTED_MDR] => MATCHED | FEE_ADJUSTED_MATCH (17695ms | AI-ReAct | tools: 1)`

C. Zero-Shot Hidden Scenario Generalization
   Added Scenario 16 (`S16_HIDDEN_COMBINED_MUTATION`) which injects 3 compound anomalies 
   simultaneously (2% MDR fee deduction + 3-day holiday settlement drift + merchant alias typo)
   to test zero-shot agentic reasoning vs. brittle deterministic heuristics.
